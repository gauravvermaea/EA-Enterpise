# EA Explorer 0.19.0

The last set before version 1.0 (D421).

## What is new

- **Updates from the repository**: System admin > Updates and `eax update` move EA Explorer to a newer release, from the
  Prod, RC or Latest channel, with a full backup first, one release at a time, and Retry or Roll back if a step fails.
- **Releases**: CI on every change, versioned releases with these notes, and a supported-versions policy.
- **Command centre** (System admin): every eax command from the browser, with a guided form, a Console for typing them
  (and `eax console`'s menu) and the history of every run; the same on `eax deploy`'s page.
- Everything accepted up to 0.18.0: drawn views in draw.io, merge and dedupe, KPI trends, OData and the report designer,
  machine access, operations insight, surveys and maturity, import formats, industry models, MCP and scenario planning.

## Also in 0.19.0: banner, schedules, settings that survive resets

- **Banner** (System admin > Banner): one message under the top bar, information, notice or urgent, with optional times
  and audience. Nothing shows unless an admin sets one.
- **Schedules** (System admin > Command centre > Schedules, `eax schedule`): eax commands that run by themselves, e.g.
  a nightly backup, a weekly smoke test, or **Demo reset every night** (`clean-restart laptop` at 02:00 with a banner).
- **persist/**: schedules, the banner and safety backups live in a folder beside `work/` that no reset deletes, as
  small JSON files you can read and edit; it is in every infrastructure backup.
- **Reset-survival test**: `eax test --reset-survival` (or the Self-test page's opt-in) proves it with a real reset.

## Also in 0.19.0: relationship attributes and line labels
- Relationships carry the attributes the metamodel defines, per relationship type or per allowed relationship (D563, D564), edited as key : value in the relationship list, a drawn view's line Properties, Excel and MCP; required ones are checked by quality.
- Drawn view lines read `name (Type) [key:value …]`, and naming a line never hides its type; **Line labels** in the toolbar hides the values on busy diagrams (D565).
- Migration 0047 adds the table that limits an attribute to some allowed relationships.

## Also in 0.19.0: ADM iteration types on projects
- Each project's ADM cycle is a **Full cycle** or one of TOGAF's iterations: **Architecture Capability** (Preliminary, A), **Architecture Development** (B, C, D), **Transition Planning** (E, F), **Architecture Governance** (G, H), or **Custom** (the phases you tick). Requirements Management is always open (D571).
- The project page asks **Which iteration is this?**; anyone on the project can change it at any time, with a history of every change (D572).
- Phases left out are **frozen**: read only, never deleted, greyed on the ADM wheel and refused by the API (D573); also in MCP, project backups, templates, the report, tasks and the self-test (D574). See [docs/phase-iterations.md](../docs/phase-iterations.md).
- Migration 0048 adds the table of iteration changes.

## Also in 0.19.0: a self-test that covers the whole app
- **Every page opens**: the self-test opens every page, group, tab and sub-tab and checks each renders, has a heading and opens help on F1; the report says "pages opened N of N" (D575).
- **Real journeys** click, type and save in the run's own fixtures, as each role allowed and refused to one that is not; the smoke test runs three of them (D576).
- **More checks**: API writes area by area, and the same writes refused; database checks of history, values, relationship attribute mappings, drawn-view bindings and persist/ (D577).
- **A coverage summary** opens every report. The Self-test page shows the exact `eax test` command for what you pick, with Copy, every command-line option, and the command each past run equals. New `eax test --journey J` and `--pages-only` (D578).
- A bare *Change documents* page no longer says Loading... for ever (found by the page sweep).
- Migration 0049 keeps a run's journeys and pages-only choice.

## Also in 0.19.0: the test bench, testing from outside
- **`eax testbench`** runs every self-test check from another machine against any EA Explorer address you own, as
  people reach it, with the same names and filters as `eax test`, in **Chromium, Firefox, WebKit and Edge**
  (`--browsers`). It never runs without `--target <address> --i-own-this` (D579).
- It uses the self-test's own code and the target's own fixtures, and gives its results back to the Self-test history,
  marked *external testbench*; `--publish` sends every result, also to another installation (D580, D581).
- **Install, upgrade and load**: `eax testbench install --answers …` (the deploy wizard), `upgrade --from … --to …`
  (the version, the database migration and the data checked before and after) and `load --users … --minutes …` (k6,
  judged by testbench/thresholds.json) (D582).
- Reports in HTML, JSON and JUnit with a coverage summary; the exit code says whether it passed.
- **Test data** for every test in `testbench/data` (Excel and CSV deliveries, a metamodel workbook, documents, a survey,
  a drawn view, expected results), shared with the self-test (`/testdata` in the test runner).
- CI runs the API and UI suites on every change, and nightly an install, an upgrade from the previous release, every
  browser and a short load test. Every install guide ends with **Check your installation**
  ([docs/deployment.md](../docs/deployment.md#check-your-installation)); see [docs/testbench.md](../docs/testbench.md).

## Also in 0.19.0: starting and testing need no extra steps (D584)
- **`up` and `clean-restart` prepare everything**: the pack step copies new or changed industry packs from the pack
  source folders (zips opened, duplicates once, quick when nothing changed), then the packs load into Documents with
  *Industry packs loading n of N* on the start-up page; set the sources once with `eax packs source <folder>` or
  `EAX_PACKS_SOURCE` in the config.
- **Tests prepare their runner**: every `eax test` and every Start on the Self-test page builds the test runner first
  (seconds when current); it is also built in the background at each start (on by default). The page has no Build
  step any more (Advanced keeps Rebuild). `eax packs collect` and `eax test --build` are optional.
- **The test bench** rebuilds its test data and installs the browsers it needs before each run.

## Before you update

- A full backup is taken first (every database, every file, the configuration and the code), and kept pinned.
- The first update to this version needs `eax clean-restart` once, so the operations helper can read the releases.
