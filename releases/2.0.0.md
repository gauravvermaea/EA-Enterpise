# EA Explorer 2.0.0: Release 2

Release 2 (13 Nov 2026): a menu bar that reaches every screen, testing that works in one command, sites and remote
instances, the Docker engine, mounts and container files from the web (with alerts when a container stops working),
archived models and projects, backups proven by the self-test, and the fixes from the full self-tests.

**Before updating:** take a backup (`.\eax backup before-2.0.0`). From 1.0.0 the update runs migrations 0051 to 0067 (new
schemas such as operations, personal data, files, sites and the archive; indexes on every foreign key; nothing removed). After it, run
`.\eax test full` once: the Backups page enables its buttons when the backup checks pass.

Known: three browser journeys can fail on a busy machine (the tests' timing, not the screens); they are R3.14.

## R2.0: a usable UI with a simple menu (built 11 Nov 2026, to be accepted)

- **A menu bar**: Architecture Work, Model Admin, Project Admin, Repository & Content Framework (the Architecture
  Repository and the Content framework together) and System Admin, each a drop-down with sub-menus; on the right your own menu (your name:
  your work, your profile, Sign out) and **?** (help and documentation); at the top left the site picker, **● Local**
  (Farm Admin). Last model and Last project side by side. Every screen, tab and wizard of 1.0 is in it (a test checks
  nothing is left out). What you may not use is not shown (D586, D588, D591).
- **Wizards**: click Wizards for the wizards page, or pick one wizard from its sub-menu (D587, D591). On a project page
  the Repository and Content framework tabs sit together.
- **Find: press /** (or Ctrl+K, or the box at the top) for any function, with where it is in the menu, or content:
  models, projects and entities as you type, and Search everything (D590).
- **Menu | Classic**, a toggle at the top right: Classic keeps the menus of 1.0 for now. The left-menu tab style and the
  first sign-in question are gone (D589). This also answers R2.6 (changing the layout did nothing on most pages).
- **Farm Admin** (Super Admins), from the site picker: Sites and Connect to a site, saying what R2.1 and R2.2 bring.

See [docs/r2-0-menu.md](../docs/r2-0-menu.md) for where everything is.

## R2.0.1: testing that works, simply (in progress)

- **Two choices**: the Smoke test or the Full test, on System Admin › Tools › Self-test or with `eax test` /
  `eax test full`. Each run starts its own test container, tests, reports and removes it (D592).
- **Test data cleaned up**: each run removes what earlier runs left first; `eax test clean` and **Delete all test data**
  remove it at any time (D593).
- **Fixed**: the self-test and updates stopping with "the installation folder is not known" (the folder is now found
  from any of the installation's files the helper has, R2.8); the quality PDF and Excel of a model never measured; a
  malformed stakeholder id giving a server error; the change log's screen waiting behind its own set-up.
- `eax testbench` is no longer a command (CI keeps the test bench).
- **Model library and Project library for everyone**: both in Architecture Work (and Repository & Content Framework ›
  Libraries); the Project library has its own page, and library projects can be read by anyone with a role (D594).
- **Fixed**: the Documentation page's documents and the library's EA Explorer documentation folder not found on an
  installation (the documents were looked for in the document store's folder); reports-init showing "unhealthy" after it
  finished (R2.20). A test run does not depend on the sample data or the industry packs (D595).
- **Fixed in the self-test** (D596): the API writes run again (they were all skipped); the browser journeys wait for pop-ups, fields and choices on a slower computer; the test data is found on Windows. A server error now says what kind it was and its request id. The front door no longer lets other sites frame it or tells its nginx version.
- **Start-up finishes in one start** (D597): the industry packs load file by file beside the sample data, with progress that moves; one file that fails no longer undoes the others; Reports no longer stays "Created".
- **Security** (D598): newer cryptography, pypdf, draw.io (32.6.10), Docker CLI and PostgreSQL images, and each image takes its distribution's fixes when built.
- **Fixed**: making a gap analysis or a common analysis ("column domain does not exist"); a slow page or a project's download ending in a bare server error after 30 seconds.
- **Start-up** (D600): the API no longer runs out of memory loading the industry packs (one file at a time; 2 GB on a laptop); Reports is up within minutes and loads its dashboards afterwards; a loader that stopped says so.
- **Containers**: CPU is shown as a share of the whole machine, with the cores in use, so the total no longer passes 100% (D601).
- **Views**: Standard views is the first sub-tab and opens by default; Custom views next. A model's picture opened in draw.io shows the objects on it and their properties, relationships and allowed relationships, read only (D602, R2.7).
- **Self-test results by importance** (D604): every check critical or not, a ring chart and a functional health (Healthy, Degraded, Not healthy) in the report, on the Self-test page and at the end of `eax test`, with every failure listed.
- The Reports tab "Power BI and Excel" is now **OData**; the Classic button is gone (D603).
- **Run the failed ones again** (D605): Self-test › History or a run's results, or `eax test failed [run] [--warnings]`: only the checks that failed, in fresh test data; the results show each check then and now, and the earlier run is marked followed up when all pass. The Command centre now also takes `test full` and `test failed`.
- **Fixed**: on Windows, a self-test or command started from the web (Self-test, Run the failed ones again, the Command centre) could not start ("the working directory ... is invalid"). A backup that cannot read a file now says which set and which file.
- **The Classic screens are gone** (D606): the menu bar is the only menu; every page Classic reached is in it.
- **Fixed on Windows**: Run the failed ones again, and anything the Self-test page or the Command centre starts, now runs (the installation folder mounted the way Docker Desktop needs). A command that starts or stops containers is not run from the web on Windows: the page gives the PowerShell line instead.
- **Architecture principles as cards** (D607): grouped by area, with statement, rationale and implications; Repository › Architecture principles for everyone, and each project's Principles tab; edit on the card, add from the library, refine an enforced one.
- **The self-test checks backups** (D608): the full test ends with an infrastructure and an application backup, each restored into a scratch copy and counted, then removed; also `eax test backup`. Until they pass, the Backups page shows the commands to run instead of its buttons.
- **A test in progress keeps normal users out** (D609): who signs in meanwhile sees "Environment test in progress" and gets in when it ends; changes wait; admins see only the Self-test page.
- **Checks left** while a self-test runs, on the page and the command line, and **deleting test results** (reports, logs, videos, screenshots) from History or `eax test delete`, and by themselves after 30 days (D610).
- **Every database has its own setting** (D611): empty = the shared PostgreSQL; set one to move that database to its own container or server. System Admin › Databases and `eax databases` show where each lives; backups follow each one.
- **Fixed**: a metamodel change that waited on the report views (a pick list took over a minute to add) is saved at once; the views catch up within minutes (R2.55). The self-test's journeys use the open dialog's buttons first (R2.56).
- **A container has Properties, Logs and Terminal** (D612): Run a command is gone; the Terminal does everything it did.
- **The self-test's data can have a database of its own** (D613): set `EAX_TESTS_DB_URL`; its tables are made at the next start and `eax databases copy tests` brings earlier runs.
- **The installation's running data can have a database of its own** (D614): set `EAX_OPERATIONS_DB_URL` for backup schedules, deployments, updates, start-up status and health history; `eax databases copy operations` brings what is there.
- **The version at the top left** (D616): the release and its build (for example "1.0.0 · build 4f2a9c1"); `eax status` shows it too.
- **The bell sits with your own menu** at the right of the top bar (D617).
- **persist/ can be emptied** (D618): `eax persist` and System Admin › Persist list what survives resets and delete it, item by item or all.
- **Logs kept on disk, backed up and cleaned** (D619): every container's log, one file a day, across restarts and updates; `eax logs backup`, `eax logs clean`, nightly cleaning ("Delete logs older than"); a laptop logs at DEBUG and a server at ERROR by default; a container's Logs view has Live, Download and Kept by day.
- **The footprint measured** (D620): `eax footprint` and System Admin › Footprint, each measurement beside the one before.
- **The UI review** (D621): `eax test ui-review` takes screenshots of every main page as each role at three widths, with notes.
- **For contributors** (D615): CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md and issue and pull-request templates.
- **The SQL window is a database workspace** (D622): a tree of schemas and tables, several query tabs with colouring and completion, history and saved queries, query plans, CSV and Excel export, and each table's rows and structure.
- **The MCP page lists every tool** an assistant can use, what it does and whether it changes anything (D623).
- **Diagrams of EA Explorer itself** (D624): System Admin › Estate (logical and physical, as it runs) and docs/estate.md.
- **Logs** (D625): a log backup is taken before every cleanup, clean-restart and update; eax's own logs and the log backups open in the Logs view.
- **Archive** (D626): a model can be moved to the archive (out of the working database, whole with its history) and brought back; a Super Admin can delete one (kept until purged). Model Admin › Archive lists them.
- **Schemas, not databases** (D630): the self-test's results, the operations tables, the archive and each person's data are schemas of their own in the one database, each with its own connection string; scaling one out changes only its location.
- **Operations service** (D631) and **personal data service** (D632): containers of their own behind the front door (/api/v1/operations/..., /api/v1/me/...). When the personal data service is away the rest works and notifications wait until it is back.
- **Container platforms** (D635): EAX_FILE_STORE=database keeps the self-test's files and exports in the database; settings may come from Docker secrets; EAX_PLATFORM=managed sends self-tests to an always-on test runner service; on a server, backups go only to the mounted folder that `eax init` asks for (EAX_BACKUP_DIR).
- **Remote instances** (D634): your own list of EA Explorer instances in the site picker (top left), each opening in its own screens; Super Admins can open a recorded SSH session to an instance's host, signing in the way EAX_REMOTE_SSH_AUTH says.
- **Library models in their own schema** (D633): the reference and published library models' content lives in the library_models schema, moved at start-up in the background; every screen reads it there, and a model made from one copies across.
- **Derived entity types** (D629): in the metamodel, an entity type can be derived from another (Server > Windows Server > Database Server). It gets the base's attributes and allowed relationships plus its own, and a change to the base flows down; each entity keeps its own values. The ER diagram shows the Specialization.
- **Projects in the archive** (D628): a project can be moved to the archive from About › Back up and restore, with its documents and the models only it uses; the models other projects use stay. The Archive page has Models and Projects tabs.
- **`eax databases speed`** (D627) measures how the database compares text, to choose the indexes.
- **eax in colour, grouped, with a menu** (D636): `eax status` shows each container in its state's colour; errors, warnings and headings are coloured (`--no-color`, NO_COLOR or CI turn it off; piped output stays plain). The help is in groups, a mistyped command says "Did you mean", and `eax menu` (or `eax` alone in a terminal) asks for each option and shows the command before it runs.
- **Test data stays out of the way** (D637): the self-test's models and projects are marked as test data and left out of the lists; each run deletes its own when it ends, passed, failed or stopped (EAX_TEST_KEEP_DATA=1 keeps it); `eax test clean --dry-run` and the Self-test page's Dry run show what would go.
- **Deploy is in the site picker** (D643): Deploy EA Explorer sits at the top left with the other sites; the old System Admin address opens it.
- **Hosts** (D638): System Admin › Running › Hosts shows the Docker engine: versions, CPU, memory, disks, Docker's own disk, what each container takes, with amber and red levels and a day's history.
- **Mounts** (D639): System Admin › Running › Mounts lists every volume and bind mount, who uses it and where, with warnings; look into one read only (largest, newest and oldest files, free space, search).
- **Files in each container** (D640): Containers › a container › Files: browse, view, edit, download (a folder as a zip), upload, new folder, rename, move, copy and delete; every change in the audit trail; secrets never shown or written; off with EAX_CONTAINER_CONSOLE=off.
- **Container alerts** (D641): a watcher in the operations helper tells IT and Super Admins (the bell, a red banner, the webhooks) when a container stops, keeps restarting, is unhealthy or runs out of memory, or the host runs high, and again when it works; optional automatic restarts (EAX_ALERT_AUTO_RESTART).
- **Code coverage** (D642): with EAX_COVERAGE=on (laptops) the self-test keeps the API's code coverage with each run (coverage.html); CI keeps the unit tests' coverage.
- **Fixed**: after the personal data service came, the screens could show "no role": who am I now always goes to the main API and is never read from the browser's cache (D644).
- **Sites** (D646): one list of EA Explorer sites for everyone in the site picker (top left) and on Sites, Local first, each with a green, amber or red health; open one to sign in there with your role on that site. Super Admins add, change or remove sites; a site deployed from Deploy EA Explorer is added when it is ready.
- **Include archived** (D647): Find and the model and project lists on Architecture work have an Include archived tick that also shows the archived models and projects you may see, with what matched, read only.
- **Test results**: the coverage line, the alert check and the UI review's notes are non-critical (D645).
- **Every foreign key has an index** (D648): deleting, archiving and purging models and projects, and the self-test's clean-up, are much faster on large models; the database check flags any new key without one and any key across schemas.
- **Fixed**: Containers listed the short-lived containers of Command centre commands and updates as more "ops-1" containers, the stopped ones as problems and alerts (D649).
- **Containers say what each one is for**: a "What it is for" column on System Admin › Containers, and the same line on each container's page.
- **Containers shows only current ones**: running and starting containers, and any that stopped with an error; set-up steps that finished, switched-off services and Docker's dead containers appear only with Show stopped.
- **The SQL window says what each database, schema and table is for**: in the database list, under each schema and under each table (also shown by psql and pgAdmin, as the table's comment) (D650).
- **Fixed**: "Not working: The host CPU is high" while EA Explorer started: the host is now an alert only when a level stays above its alert line for 10 minutes (EAX_ALERT_HOST_MINUTES), never while starting, and the banner says "Needs attention" for the host (amber), "Not working" only for a container.
- **Fixed**: a self-test started while the sample data was still loading stopped at once with "duplicate key value violates unique constraint model_ancestors_pkey"; models made at the same moment no longer collide (D651).
- **Test straight after a restart**: a self-test waits only for the services it tests to finish starting (up to 10 minutes, saying which), never for the sample data or industry packs (D652).
- **Container files like Windows Explorer**: a folder tree, double click to open, a File menu, Back, Forward and Up; folders that are links (such as /bin and /lib) now open and show what is in them (D653).
- **Backup buttons always shown**: until a self-test proves backups from the web, the buttons are disabled with the reason, and "Use them anyway" lets you go on (recorded in the audit trail) (D654).
- **Full self-test fixes**: the backup trial restore's checksum check works in the backup image; a model you may not read answers "not found" instead of a server error; the test bench state answers within 30 seconds; the ADM iteration shows straight after saving (D655).
- **No more stuck self-tests**: a run whose test runner was restarted or removed closes itself as stopped within a few minutes (or at once when you press Stop), and no longer blocks a new run (D656).
